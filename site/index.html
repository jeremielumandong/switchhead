A very fast, native Git client. switchhead reads history in process with gitoxide, streams the commit graph while it is still being read, and runs every change through your own git, so hooks, credential helpers, SSH agents, signing and LFS behave exactly like the command line.

    How it stays fast
    
  
    Reads in process.
    Writes through git.
    
  
    The two halves of a Git client want opposite things. Reading history wants raw speed; changing a repository wants to behave exactly like your terminal. switchhead does both on purpose.
    
  
    
    
    
      
    gitoxide · in process
    
      
    Read
    
      
      
        
    • Log walk in date order with the commit-graph file, sent in batches with their graph rows
      • 
        
    • Refs, commit diffs and blob diffs (histogram, word-level highlights)
      • 
        
    • Columnar commit store: ids, times, interned authors, summaries in one arena
      • 
        
    • Pure, incremental lane layout, unit-tested on synthetic histories
      • 
      
    
    
    
    
    
      
    
    
    
    
      
    system git · child process
    
      
    Write
    
      
      
        
    • Commit, stage, checkout, merge, rebase, push, stash, tag: all through git
      • 
        
    • Status with --porcelain=v2: fsmonitor and the untracked cache
      • 
        
    • Progress streamed to the status bar; cancel kills git's whole process group
      • 
        
    • Your hooks, signing, LFS and credential prompts behave like the command line
      • 
      
    
    
    
  
    

    



    
  
    
    
    
      
    Performance budgets
    
      
    Fast where it matters.
    
    
    
    
    Every git operation logs its time, and the status bar shows how long the first rows took. These are the budgets the app is built against.
    
  
    

  
    
    
    Whole history of git/git, all refs, date order
    
    
    switchhead
    1.3 s
    
    
    git log
    ≈2.6 s
    
    
    First rows appear in 94 ms; the list is usable long before the walk finishes. Without a commit-graph file gix needs 1.9 s before the first batch, so switchhead uses it whenever git wrote one.
    
  
    

  
    
    
    < 300 mscold start
    
    
    < 100 msopen a repo to first graph rows
    
    
    < 500 msfirst rows on a 1M-commit repo
    
    
    < 30 msswitch commits, file list shown
    
    
    < 50 msa typical file diff
    
    
    < 300 msstatus of a 100k-file work tree
    
    
    < 16 msswitch repo tabs, state stays in memory
    
    
    < 200 msscan a folder of ~1,000 directories

    Local changes
    
      
    Stage a line,
    not a guess.
    
      
    Stage, unstage or discard whole files, single hunks, or individual lines picked in the diff. The commit box counts your subject (amber past 50, red past 72), loads the last message on Amend and restores your draft when you turn it off. When a hook says no, its full output sits right under the box.
    
      
      
        
    • Space or Enter stages, Tab switches lists, Ctrl/Cmd+Enter commits
      • 
        
    • Ignore a file, its extension or a folder in one click
      • 
        
    • Assume-unchanged and skip-worktree from the context menu
      • 
        
    • Destructive actions always ask first
      • 
      
    
    
    
    
    
      
      
    
    
  
    

    


    
  
    
    
    
    
  
    

    



    
  
    
    
    
      
    Coming next · AI assistant
    
      
    Bring the coding CLI
    you already use.
    
      
    Claude Code, Codex CLI, Gemini CLI or your own. It writes commit messages from the staged diff, proposes conflict resolutions, explains git commands and reviews branches. You review and apply every proposal.
    
      
    Safety lives in the server
    
      
      
        
    • The CLI runs in a private, empty temp folder, never in your repository
      • 
        
    • Its own shell and file-edit tools are turned off
      • 
        
    • Its only tools are switchhead's read-only git MCP server, scoped to one repository
      • 
        
    • It returns proposals; the app applies them only after you review them
      • 
        
    • switchhead never reads, stores or proxies a CLI's credentials
      •

    Build from source.
    
  
    Rust 1.97 or newer (pinned in rust-toolchain.toml) and git on your PATH.
    
  
    
    
    Linux dependencies (Debian / Ubuntu)
    $ sudo apt-get install -y libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev \
    libxcb1-dev libvulkan-dev libfontconfig-dev libfreetype-dev libssl-dev pkg-config
    
    
    Run
    $ git clone https://github.com/jeremielumandong/switchhead
$ cd switchhead
$ cargo run --release -p switchhead-app -- ~/code
    
    
    Checks
    $ cargo fmt --all
$ cargo clippy --workspace --all-targets -- -D warnings
$ cargo test --workspace
    
  
    
  
    Pass a repository to open it, or a plain folder to scan it for every repository inside.
